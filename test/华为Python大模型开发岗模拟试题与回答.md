# 一、Python 核心基础

## 1. GIL、多线程、多进程与协程

### 题目 1：什么是 GIL？它为什么存在？

参考回答：

GIL 是 CPython 中的全局解释器锁，同一时刻只允许一个线程执行 Python 字节码。

它主要用于保护 CPython 的内部对象和引用计数，避免多个线程同时修改对象导致内存破坏。它不是操作系统层面的锁，也不是所有 Python 实现都有，例如 Jython、IronPython 就没有同样的 GIL。

GIL 的影响是：

- 多线程适合 IO 密集型任务；
- 多线程无法让纯 Python CPU 密集型代码真正并行；
- 多进程拥有独立解释器和 GIL，可以利用多个 CPU 核心；
- C 扩展执行耗时计算时可能主动释放 GIL。

### 题目 2：GIL 什么时候会释放？

参考回答：

常见情况有：

1. 线程执行阻塞 IO，例如网络、文件、数据库操作；
2. 调用某些 C 扩展时，例如部分 NumPy、图像处理库；
3. 线程执行时间片结束后，解释器会进行线程调度。

不能简单地说“CPU 任务一定不会释放 GIL”。如果 CPU 计算发生在释放 GIL 的 C/C++ 扩展中，也可能实现并行。纯 Python 代码中的 CPU 密集型循环通常无法通过多线程提速。

### 题目 3：大模型应用中如何选择线程、进程和 asyncio？

参考回答：

- 调用 LLM API、数据库、HTTP、向量库：IO 密集，适合 `asyncio`；
- 纯 Python 文本计算、复杂数据处理：CPU 密集，适合多进程；
- 调用阻塞式第三方 SDK：可以使用线程池；
- GPU 推理：通常由底层框架管理并行，重点考虑 GPU 显存、批处理和请求队列。

```python
# IO 密集任务
results = await asyncio.gather(
    call_llm_async("问题1"),
    call_llm_async("问题2"),
)
```

如果是 CPU 密集型任务，可以使用 `ProcessPoolExecutor`，通过多进程绕开单个解释器的 GIL。

## 2. 深浅拷贝与可变默认参数

### 题目 1：浅拷贝和深拷贝有什么区别？

参考回答：

浅拷贝只复制最外层对象，内部嵌套对象仍然共享引用。深拷贝会递归复制所有嵌套对象，互不影响。

```python
import copy

a = [[1, 2]]
b = copy.copy(a)
c = copy.deepcopy(a)

b[0].append(3)
```

此时 `a` 也会变成 `[[1, 2, 3]]`，因为 `a` 和 `b` 共享内部列表；但 `c` 不会受到影响。

### 题目 2：下面代码有什么问题？

```python
def func(items=[]):
    items.append(1)
    return items
```

参考回答：

默认参数只在函数定义时创建一次，不是每次调用函数时重新创建。因此多次调用会共享同一个列表。

正确写法：

```python
def func(items=None):
    if items is None:
        items = []
    items.append(1)
    return items
```

### 题目 3：构建数据集时如何避免共享引用问题？

参考回答：

不能直接复用同一个可变字典或列表：

```python
template = {"messages": []}
data = [template] * 100
```

这里 100 个元素指向同一个字典。可以使用推导式创建独立对象：

```python
data = [{"messages": []} for _ in range(100)]
```

核心原则是：`*` 复制的是引用，不是对象本身。

## 3. 实例方法、类方法和静态方法

### 题目 1：三者有什么区别？

参考回答：

实例方法第一个参数通常是 `self`，可以访问实例属性；类方法使用 `@classmethod`，第一个参数通常是 `cls`，常用于工厂方法；静态方法使用 `@staticmethod`，不自动传入 `self` 或 `cls`，本质上是放在类命名空间中的普通函数。

```python
class User:
    def __init__(self, name):
        self.name = name

    def show(self):
        return self.name

    @classmethod
    def from_dict(cls, data):
        return cls(data["name"])

    @staticmethod
    def validate_name(name):
        return bool(name)
```

### 题目 2：为什么使用类方法工厂？

参考回答：

类方法通过 `cls` 创建当前类实例。子类继承后调用工厂方法时，`cls` 会指向子类，因此能够正确创建子类对象，比写死具体类名更利于扩展。

### 题目 3：大模型项目中静态方法适合放什么逻辑？

参考回答：

适合放与实例状态、类状态都无关的工具函数，例如 Prompt 格式化、文本清洗、Token 长度估算、JSON 字段校验和相似度计算。

## 4. Python 垃圾回收

### 题目 1：Python 主要使用什么垃圾回收机制？

参考回答：

CPython 主要使用引用计数、循环垃圾回收和分代回收。引用计数为零时对象通常会立即释放。

### 题目 2：什么是循环引用？

参考回答：

对象之间互相引用，但外部已经没有任何引用时，就形成循环引用。引用计数无法处理这种情况，Python 的循环垃圾回收器会检测不可达的引用环并回收。

### 题目 3：什么是分代回收？

参考回答：

Python 根据对象存活时间划分不同代。新对象回收频繁，长期存活对象回收较少，利用了多数对象生命周期较短这一规律，可以减少回收开销。

大模型服务还要注意：大对象释放不一定立即归还操作系统，GPU 显存也由深度学习框架单独管理。

## 5. 迭代器、生成器和 `yield`

### 题目 1：什么是迭代器？

参考回答：

迭代器是实现了 `__iter__()` 和 `__next__()` 方法的对象。调用 `next()` 时只返回一个元素，因此适合处理大数据。

### 题目 2：生成器和列表有什么区别？

参考回答：

列表一次性计算并保存全部结果；生成器通过 `yield` 延迟计算，只在需要时生成下一个结果，因此适合大文件、数据集和大模型流式输出。

### 题目 3：如何使用 `yield` 实现大模型流式输出？

参考回答：

```python
def generate_stream():
    try:
        for token in model_stream():
            yield f"data: {token}\n\n"
    except Exception as exc:
        yield f"data: [ERROR] {exc}\n\n"
```

FastAPI 可以使用 `StreamingResponse` 返回这个生成器。`yield` 会暂停函数并保存执行现场，客户端读取下一段数据时继续执行，不需要将完整回答放入内存。

# 二、异步 IO 与 Web 工程

## 6. asyncio、事件循环和并发限制

### 题目 1：什么是事件循环？

参考回答：

事件循环不断检查哪些协程可以继续执行。协程执行到 `await` 并等待网络响应时，会把执行权交还事件循环，使其他任务继续运行。

### 题目 2：为什么协程中不能直接执行 CPU 密集任务？

参考回答：

事件循环线程需要持续调度其他协程。如果协程执行长时间 CPU 计算且没有 `await`，整个事件循环都会被阻塞。此类任务应放入线程池或进程池，纯 Python CPU 任务通常优先进程池。

### 题目 3：如何限制并发调用大模型 API？

参考回答：

```python
semaphore = asyncio.Semaphore(10)

async def call_with_limit(prompt):
    async with semaphore:
        return await call_llm(prompt)
```

信号量最多允许 10 个协程同时进入临界区，可以避免超过模型 QPS、连接数过高、内存无限增长和大量限流错误。

## 7. 异步异常处理

### 题目 1：协程中的异常如何捕获？

参考回答：

使用普通的 `try...except`。多个协程通过 `asyncio.gather()` 执行时，可以设置 `return_exceptions=True`，使单个任务异常作为结果返回，而不是直接中断全部任务。

### 题目 2：如何处理任务取消？

参考回答：

客户端断开或服务超时时，协程可能收到 `asyncio.CancelledError`。应该完成资源清理，然后继续抛出取消异常，保持事件循环的取消语义。

### 题目 3：失败后是否应该无限重试？

参考回答：

不应该。应该设置最大重试次数、指数退避和总超时时间，只重试临时性错误；参数错误、鉴权错误等不应重试。多次失败后应执行降级或返回错误。

## 8. FastAPI 与 Pydantic

### 题目 1：Pydantic 的作用是什么？

参考回答：

Pydantic 用于定义请求和响应数据结构，并进行类型校验和转换。FastAPI 可以利用它自动校验字段、生成 OpenAPI 文档并返回结构化错误。

### 题目 2：FastAPI 中同步函数和异步函数有什么区别？

参考回答：

异步函数适合异步 IO；阻塞 SDK 应放入线程池；CPU 密集任务可以放入进程池。仅仅把函数声明为 `async` 并不会自动把同步阻塞代码变成异步。

### 题目 3：FastAPI 如何处理大量请求？

参考回答：

使用异步 IO、连接池、请求超时、信号量、队列、限流和多进程 worker，并监控 CPU、内存、连接数、队列长度和延迟。多 worker 可能重复加载模型，需要注意内存和 GPU 显存。

# 三、计算机网络

## 9. TCP 四次挥手与 TIME_WAIT

### 题目 1：TCP 为什么需要四次挥手？

 （TCP 报文控制位：SYN / ACK / FIN）

1. **SYN（Synchronize，同步）**
作用：**请求建立连接**，携带双方初始序列号
👉 三次握手用到
1. **ACK（Acknowledgment，确认应答）**
作用：**确认收到对方报文**，几乎通信全程都会出现
👉 握手、传输、挥手都有
1. **FIN（Finish，结束）**
作用：**本方不再发送数据，请求关闭连接**
👉 四次挥手使用

参考回答：

TCP 是全双工连接，双方发送方向需要分别关闭。主动方发送 FIN，服务端 ACK；服务端处理完剩余数据后发送 FIN，客户端再 ACK。服务端收到 FIN 后可能仍有数据要发送，所以 ACK 和 FIN 通常不是同一个报文。

### 题目 2：主动关闭方为什么进入 TIME_WAIT？

参考回答：

主要为了确保最后一个 ACK 丢失时可以重发，并让旧连接中的延迟报文在网络中消失，避免影响新连接。TIME_WAIT 通常持续 2MSL。

### 题目 3：大量 TIME_WAIT 怎么解决？

参考回答：

大量 TIME_WAIT 说明本机大量主动关闭连接，常见于短连接 HTTP 请求。应优先使用 Keep-Alive、连接池和复用 HTTP 客户端，减少短连接；不要简单依赖系统参数，应结合系统版本和网络环境谨慎调整。

## 10. CLOSE_WAIT

### 题目 1：CLOSE_WAIT 如何产生？

参考回答：

对端发送 FIN 后，本机 TCP 层返回 ACK 并进入 CLOSE_WAIT，表示对方已经关闭发送方向，但本地应用还没有调用 `close()`。

### 题目 2：大量 CLOSE_WAIT 如何排查？

参考回答：

使用 `ss -ntap` 找到对应进程，检查应用日志、异常堆栈、HTTP 和数据库连接是否缺少关闭，检查连接池是否正确归还连接，并使用 `py-spy dump` 查看是否卡在阻塞或死循环。

Python 中应优先使用上下文管理器，保证异常分支也能释放资源。

### 题目 3：TIME_WAIT 和 CLOSE_WAIT 的区别是什么？

参考回答：

TIME_WAIT 是本机主动关闭后的等待状态，通常是短连接过多；CLOSE_WAIT 是对端关闭后本机应用尚未关闭，长期大量堆积通常说明应用连接泄漏。

## 11. HTTP SSE 流式协议

### 题目 1：SSE 和 WebSocket 有什么区别？

参考回答：

SSE 基于 HTTP，主要是服务端向客户端单向推送；WebSocket 是全双工通信。大模型只需要持续输出 Token 时，SSE 实现简单并且容易接入现有 HTTP 基础设施。

### 题目 2：SSE 数据格式是什么？

参考回答：

```text
data: {"token": "你好"}\n\n
```

响应头通常为 `Content-Type: text/event-stream`，并配合 `Cache-Control: no-cache` 和长连接设置。每个事件通常以两个换行符结束。

### 题目 3：SSE 输出异常怎么办？

参考回答：

需要处理上游超时、客户端断开和服务端异常。服务端应发送结构化错误事件，并取消上游任务、关闭连接、释放信号量和其他资源。

## 12. TCP 滑动窗口

### 题目 1：什么是 TCP 滑动窗口？

参考回答：

滑动窗口允许发送方在等待确认前连续发送多个数据包，提高链路利用率。窗口大小表示当前最多可以发送但尚未确认的数据量。

### 题目 2：接收窗口和拥塞窗口有什么区别？

参考回答：

接收窗口由接收方通告，防止接收缓冲区溢出；拥塞窗口由发送方根据网络拥塞情况调整，防止网络被压垮。实际发送窗口通常取两者较小值。

### 题目 3：它和大模型服务的请求队列有什么相似点？

参考回答：

两者都限制“在途任务数量”。TCP 限制未确认数据量，大模型服务可以限制同时生成的请求数、用户并发数、队列长度和每秒 Token 数，避免下游变慢时请求无限堆积。

# 四、Linux、调试与并发基础

## 13. `ss -ntap` 与网络状态排查

### 题目 1：`ss -ntap` 参数含义是什么？

参考回答：

- `-n`：不解析域名和服务名；
- `-t`：显示 TCP；
- `-a`：显示所有连接；
- `-p`：显示关联进程。

### 题目 2：Recv-Q 和 Send-Q 不为 0 代表什么？

参考回答：

对已建立连接而言，Recv-Q 表示已经到达内核但应用还没有读取的数据；Send-Q 表示应用已经发送但尚未完成发送或确认的数据。长期堆积可能说明应用读取不及时、网络拥塞或事件循环被阻塞。

### 题目 3：FastAPI 大量请求卡住如何定位？

参考回答：

使用 `ss -ntap` 查看连接状态，使用 `py-spy top` 和 `py-spy dump` 查看 CPU 与线程堆栈，再检查请求队列、线程池、连接池、下游 LLM 延迟和日志。

## 14. gdb、py-spy 与性能排查

### 题目 1：gdb 中 `bt` 和 `info threads` 的作用是什么？

参考回答：

`bt` 查看当前线程调用栈；`info threads` 查看所有线程；`thread ID` 切换线程；`thread apply all bt` 查看所有线程堆栈。gdb 更适合定位解释器、C 扩展或底层崩溃。

### 题目 2：py-spy 解决什么问题？

参考回答：

`py-spy` 可以不修改代码地观察 CPU 热点、线程堆栈、锁等待和火焰图。

```bash
py-spy top --pid <PID>
py-spy dump --pid <PID>
py-spy record -o profile.svg --pid <PID>
```

### 题目 3：如何区分 CPU 高和 IO 阻塞？

参考回答：

CPU 高且 `py-spy` 显示某函数持续运行，通常是计算或死循环；CPU 低但连接和请求很多，通常是等待网络、锁、队列或连接池。需要结合 CPU、网络、日志和线程堆栈判断。

## 15. 进程、线程和协程

### 题目 1：三者有什么区别？

参考回答：

进程拥有独立地址空间，隔离性强但开销大；线程共享进程地址空间，创建成本低但需要锁保护；协程是用户态调度单元，切换成本低，但需要通过 `await` 主动让出控制权。

### 题目 2：什么是上下文切换？

参考回答：

上下文切换是 CPU 从一个执行单元切换到另一个执行单元，需要保存和恢复寄存器、栈和程序计数器。通常进程切换成本高于线程，线程高于协程。

### 题目 3：为什么不能无限增加并发？

参考回答：

并发会消耗内存、文件描述符、连接、线程、API 配额、GPU 显存和数据库连接池。超过处理能力后会出现排队、超时、重试风暴和级联故障，因此需要通过压测确定合理并发量。

# 五、算法与数据结构

## 16. LeetCode 91：解码方法

### 题目 1：动态规划思路是什么？

参考回答：

定义 `dp[i]` 为前 `i` 个字符的解码方法数。当前字符不是 `0` 时，可以单独解码，增加 `dp[i-1]`；最后两个字符在 `10` 到 `26` 之间时，可以合并解码，增加 `dp[i-2]`。

### 题目 2：边界条件有哪些？

参考回答：

`dp[0] = 1`，表示空字符串有一种空解码方式。`0` 不能单独解码，只有和前面的 `1` 或 `2` 组成 `10`、`20` 时才有效；`06`、`30` 等情况无效。

### 题目 3：如何优化空间复杂度？

参考回答：

因为 `dp[i]` 只依赖前两个状态，所以只保存前一个和前两个值即可，将空间复杂度从 `O(n)` 降到 `O(1)`，时间复杂度仍为 `O(n)`。

## 17. 堆排序

### 题目 1：堆排序的基本原理是什么？

参考回答：

以大顶堆升序排序为例：先建大顶堆，堆顶是最大值；将堆顶与末尾元素交换，缩小堆范围；对新的堆顶执行 `heapify`；重复直到排序完成。

### 题目 2：如何判断数组是否满足大顶堆？

参考回答：

对于下标 `i`，左孩子是 `2i+1`，右孩子是 `2i+2`。所有非叶子节点都必须大于等于存在的孩子节点。

### 题目 3：堆排序复杂度和稳定性如何？

参考回答：

建堆为 `O(n)`，每次调整为 `O(log n)`，总时间复杂度为 `O(n log n)`，额外空间复杂度为 `O(1)`，通常是不稳定排序。

## 18. 海量字符串、哈希集合与布隆过滤器

### 题目 1：如何快速判断字符串是否存在？

参考回答：

内存足够时使用 Python `set`，平均查询复杂度为 `O(1)`。但哈希表需要保存字符串对象、哈希值和槽位，因此内存开销较大。

### 题目 2：布隆过滤器的原理是什么？

参考回答：

布隆过滤器由位数组和多个哈希函数组成。插入时将多个哈希位置设为 1；查询时只要有一个位置为 0，就一定不存在；全部为 1 时可能存在，也可能是假阳性。

### 题目 3：内存不足时如何处理海量字符串？

参考回答：

可以使用布隆过滤器做第一层过滤，再通过分片哈希、外部排序、磁盘 KV、Redis、RocksDB 或分布式数据库确认真实结果。布隆过滤器不能单独作为最终判断。

# 六、RAG

## 19. RAG 完整链路

### 题目 1：请讲解完整流程。

参考回答：

```text
文档加载
→ 文本清洗
→ 文档切分
→ Embedding 向量化
→ 写入向量数据库
→ 用户问题向量化或改写
→ 向量/关键词检索
→ 重排序
→ Prompt 组装
→ LLM 生成
→ 引用和结果校验
```

### 题目 2：为什么 RAG 可以减少幻觉？

参考回答：

RAG 在推理时提供外部知识，并通过 Prompt 约束模型基于证据回答、输出引用、证据不足时拒答。但 RAG 不能自动消除幻觉，错误检索、上下文冲突和 Prompt 不严谨仍会导致错误。

### 题目 3：RAG 和微调有什么区别？

参考回答：

RAG 在推理时动态提供知识，适合频繁变化和需要引用来源的知识；微调改变模型参数，适合固定格式、风格和任务能力。频繁更新的企业知识通常更适合 RAG。

## 20. Chunk 切分与上下文

### 题目 1：chunk 为什么不能无限大？

参考回答：

chunk 过大会引入噪声、降低向量表示准确性、增加 Token 消耗并分散模型注意力；chunk 过小则会丢失上下文、拆散标题正文和表格。

### 题目 2：overlap 的作用是什么？

参考回答：

overlap 让相邻 chunk 共享一部分文本，减少关键信息被边界切断的问题。但 overlap 过大会导致存储增加、结果重复和上下文浪费。

### 题目 3：chunk 大小如何调优？

参考回答：

应结合文档类型、问题长度、Embedding 模型、上下文窗口和评估集进行实验。优先按标题、段落和语义边界切分，对长文档、表格和代码使用不同策略。

## 21. RAG 召回效果优化

### 题目 1：召回不准如何排查？

参考回答：

检查文档完整性、清洗、chunk、Embedding 模型、query 改写、Top-K、关键词匹配、reranker、索引参数和 Prompt。首先区分“没有召回”还是“召回了但排序错误”。

### 题目 2：什么是混合检索？

参考回答：

混合检索同时使用 BM25 等关键词检索和向量语义检索。关键词检索擅长编号、型号和专有名词，向量检索擅长同义表达和语义相似，最终可以通过加权或排名融合合并结果。

### 题目 3：reranker 的作用是什么？

参考回答：

先使用速度较快的向量检索召回候选文档，再用 reranker 对问题和文档进行精细相关性判断，最后选择少量高质量结果放入 Prompt。它能提高精度，但会增加延迟。

## 22. 向量数据库

### 题目 1：FAISS、Chroma、Milvus 有什么区别？

参考回答：

FAISS 偏底层，适合单机内存索引和实验；Chroma 更偏应用层，适合本地开发和小规模 RAG；Milvus 是分布式向量数据库，适合海量向量、持久化、扩展和生产服务。

### 题目 2：什么时候使用 FAISS？

参考回答：

数据量不大、单机内存足够且不需要复杂服务治理时可以使用 FAISS。它性能高、部署简单，但持久化、高可用、权限和扩展能力需要自行建设。

### 题目 3：向量库内存放不下怎么办？

参考回答：

可以使用磁盘索引、向量量化、降低维度、清理重复文档、数据分片、冷热分层，或者使用 Milvus、pgvector、Elasticsearch 等支持持久化和扩展的系统。

# 七、幻觉抑制与效果评估

## 23. 大模型幻觉

### 题目 1：什么是大模型幻觉？

参考回答：

幻觉是模型生成了看似合理但没有事实依据、与输入不一致或实际错误的内容。原因可能包括知识不完整、问题超出能力、Prompt 约束不足、检索错误和上下文冲突。

### 题目 2：如何抑制 RAG 场景中的幻觉？

参考回答：

提高文档和召回质量，引入混合检索和 reranker，要求基于证据回答并输出引用，证据不足时拒答，使用较低 temperature、结构化输出和后校验，并对高风险结果人工审核。

### 题目 3：如何量化评估 RAG 效果？

参考回答：

检索侧可以评估 Recall@K、Precision@K、MRR、nDCG 和证据覆盖率；生成侧可以评估答案正确率、忠实度、引用准确率、拒答准确率、幻觉率、延迟、首 Token 延迟和 Token 成本。

# 八、Agent 与 LangChain

## 24. CoT、ReAct 与 Tool Calling

### 题目 1：什么是 CoT？

参考回答：

CoT 是 Chain of Thought，让模型分步骤完成复杂推理。在生产环境中不一定需要向用户展示完整思维过程，可以只输出结论和必要依据。

### 题目 2：什么是 ReAct？

参考回答：

ReAct 将推理和行动结合起来，典型循环是“思考问题—选择工具—执行工具—观察结果—再次推理—输出答案”。例如查询实时库存时调用库存工具，而不是让模型凭记忆猜测。

### 题目 3：Tool Calling 的基本流程是什么？

参考回答：

服务端向模型提供工具描述和参数 Schema，模型决定是否调用并生成参数；服务端校验参数、执行工具，再将结果返回给模型生成最终回答。真正执行工具必须由服务端完成，不能直接信任模型输出。

## 25. Agent 工具调用失败

### 题目 1：参数错误怎么办？

参考回答：

使用严格 JSON Schema、Pydantic、枚举和范围校验；校验失败后返回结构化错误，让模型有限次数重新生成。工具参数不能直接用于 SQL、Shell 或内部请求。

### 题目 2：工具执行超时怎么办？

参考回答：

设置工具调用超时，超时后可以使用缓存、备用工具或降级为普通回答，并限制 Agent 最大循环次数，避免无限重试。

### 题目 3：如何避免 Agent 乱调用工具？

参考回答：

明确工具适用条件，增加权限校验、调用次数上限、高风险操作确认、工具结果校验和完整日志。重要业务最好使用确定性状态机，而不是完全依赖自由 Agent。

## 26. LangChain 选型

### 题目 1：为什么使用 LangChain？

参考回答：

LangChain 提供 Prompt、模型、Retriever、Tool、Agent、Memory 和输出解析器等组件，适合快速搭建原型和接入多种模型。

### 题目 2：LangChain 有什么缺点？

参考回答：

抽象层较多、调用链较深、默认行为不易完全控制，版本变化可能影响兼容性，出现问题时调试和性能优化较复杂。

### 题目 3：什么时候自研，什么时候使用 LangChain？

参考回答：

原型阶段、简单业务和快速验证适合 LangChain；线上核心链路、对延迟稳定性要求高、流程固定且需要精确控制时适合自研。可以先用 LangChain 验证，再将核心链路逐步剥离出来。

# 九、模型服务、Prompt 与稳定性

## 27. OpenAI 风格接口

### 题目 1：什么是 OpenAI 风格接口？

参考回答：

它是一种统一的 HTTP API 形式，通常包含 `model`、`messages`、`temperature` 和 `stream` 等字段。统一协议可以降低模型厂商耦合，方便切换模型和实现模型网关。

### 题目 2：同步调用和异步调用有什么区别？

参考回答：

同步调用会阻塞当前线程；异步调用等待网络时可以让出执行权，适合高并发 IO 服务。但底层 SDK 必须真正支持异步，否则仍会阻塞事件循环。

### 题目 3：模型服务如何实现请求队列？

参考回答：

请求先进入队列，再由固定数量 worker 消费。队列可以削峰、控制并发、实现优先级和批处理，但必须设置上限、超时和拒绝策略，避免队列自身造成内存增长。

## 28. Prompt、Few-shot 与结构化输出

### 题目 1：好的 Prompt 应该包含什么？

参考回答：

应包含角色、任务目标、输入、输出格式、约束条件、示例、异常处理方式和必要上下文。RAG Prompt 还应明确只能基于参考资料回答，资料不足时拒答。

### 题目 2：Few-shot 有什么作用？

参考回答：

Few-shot 通过少量输入输出样例让模型理解任务规则、格式和边界。示例不宜过多，否则会消耗上下文并可能引入冲突。

### 题目 3：如何让模型稳定输出 JSON？

参考回答：

使用 JSON Schema、字段类型、必填项和示例，优先使用模型原生结构化输出，服务端使用 Pydantic 解析。解析失败后进行有限修复，仍失败则返回错误或执行降级。

## 29. temperature

### 题目 1：temperature 的作用是什么？

参考回答：

temperature 控制采样随机程度。值低时输出更确定、稳定，值高时输出更多样。它影响 Token 选择概率，不会改变模型本身的知识。

### 题目 2：哪些场景适合低 temperature？

参考回答：

RAG 问答、信息抽取、分类、审核、代码生成和结构化 JSON 输出通常适合低 temperature，因为这些任务更重视一致性和准确性。

### 题目 3：temperature 为 0 能消除幻觉吗？

参考回答：

不能。它只能降低随机性，不能修复错误知识、错误检索或不严谨 Prompt。还需要证据约束、拒答策略、后校验和评估监控。

## 30. 超时、限流、熔断与降级

### 题目 1：大模型服务如何设计超时？

参考回答：

至少设置连接超时、读取超时、总请求超时、队列等待超时和工具调用超时。流式请求还要设置单个 Token 间隔超时，避免连接无期限占用。

### 题目 2：什么是熔断？

参考回答：

当下游持续失败时，熔断器暂时阻止新请求访问下游，快速失败或降级。常见状态是 Closed、Open 和 Half-Open，用于防止故障扩散。

### 题目 3：有哪些降级策略？

参考回答：

可以切换备用模型、降低回答长度、使用缓存、直接返回检索原文、使用规则系统或暂停非核心功能。降级结果应对用户透明。

# 十、项目高频追问

## 31. 项目介绍

### 题目 1：请介绍一个大模型项目。

参考回答：

我负责的是一个基于 RAG 的企业知识库问答系统，链路包括文档解析、结构化切分、Embedding、向量检索、重排序、Prompt 组装和大模型生成。

项目中主要解决了三个问题：原始文档结构复杂、纯向量检索对产品编号召回不准，以及高并发调用模型时出现超时和连接堆积。

我的优化包括按标题和语义边界切分，引入关键词和向量混合检索，使用 reranker 重新排序，并增加异步调用、信号量、超时和降级。同时建立 Recall@K、答案准确率和幻觉率评估集。

### 题目 2：项目中最困难的问题是什么？

参考回答：

不能只回答“模型效果不好”，应该把问题拆成文档处理、召回、Prompt 和生成四个层面，先判断是没有召回正确文档，还是召回正确但模型没有正确使用证据，再分别优化。

### 题目 3：如何证明优化有效？

参考回答：

使用固定测试集和对照实验，固定问题集合、Embedding 和大模型版本，对比优化前后的 Recall@5、答案正确率、引用准确率、幻觉率、延迟和 Token 成本。

## 32. 线上高并发调用 LLM

### 题目 1：如何防止压垮下游模型？

参考回答：

可以设计多层保护：

```text
用户限流
→ 网关限流
→ 服务端信号量
→ 请求队列
→ 下游超时
→ 重试和熔断
→ 备用模型降级
```

同时监控 QPS、并发数、队列长度、P95/P99 延迟、Token 消耗、超时率和错误率。

### 题目 2：为什么不能无限重试？

参考回答：

下游故障时无限重试会产生重试风暴，使服务更加拥塞。应该使用指数退避、随机抖动、最大重试次数和总截止时间，并区分临时错误与永久错误。

### 题目 3：如何处理客户端中途断开？

参考回答：

检测发送异常后取消上游 LLM 任务，关闭上游连接，释放信号量和队列资源，并记录取消原因，避免客户端不再需要结果但服务端仍继续生成。

## 33. 开源项目源码阅读

### 题目 1：读过哪些项目？

参考回答：

可以介绍真正读过的 LangChain、FAISS、FastAPI 或向量数据库客户端。重点不在于罗列项目，而是讲清楚某个模块的入口、核心数据结构、调用链和性能特点。

### 题目 2：阅读源码重点关注什么？

参考回答：

重点关注入口函数、数据结构、调用链、异常处理、并发模型、缓存、连接池、扩展点、日志和性能瓶颈。

### 题目 3：不熟悉某个源码模块如何回答？

参考回答：

应诚实说明范围，例如：“我主要读过它的检索和调用链部分，底层索引实现没有深入到每个函数，但我理解其核心流程是……”不要假装熟悉所有源码。

# 十一、三面综合题

模型推理通常由 C/C++、CUDA 或远程模型服务完成，因此 Python 主要承担业务编排、协议适配、数据处理和服务治理。生产环境需要配合类型校验、测试、限流、监控和性能分析。

关键是不只会调用 API，还要理解请求如何进入服务、如何排队、如何调用模型、如何返回，以及异常时如何恢复。

建议按照下面顺序准备：

1. GIL、线程、进程、asyncio；
2. `yield` 和 SSE 流式输出；
3. RAG 全链路和召回优化；
4. TIME_WAIT、CLOSE_WAIT、`ss -ntap`；
5. Agent、Tool Calling、LangChain 选型；
6. 超时、限流、熔断、降级；
7. 幻觉抑制和效果评估；
8. LC91、堆排序、布隆过滤器；
9. 可变默认参数、深浅拷贝；
10. 项目介绍和项目问题深挖。

面试回答建议遵循：

```text
先给结论
→ 解释底层原理
→ 结合大模型项目场景
→ 说明优缺点和异常处理
```

例如回答“为什么使用 asyncio”时，可以说：

> 大模型 API 调用主要是网络 IO。协程在等待网络响应时会把执行权交还给事件循环，因此一个线程可以管理大量 IO 请求。但协程不适合直接执行长时间 CPU 计算，否则会阻塞整个事件循环；这类任务需要放入线程池或进程池。
