查询运行链

  1. 用户在前端提问，请求发往 /api/chat/stream
  2. Agent 规划器调用 LLM 决定检索策略：全局检索 / 定向检索 / 概念定位（Wiki）
  3. Wiki 概念层提供别名扩展，同一概念的不同叫法都能命中；概念定位直接召回锚点 chunks
  4. 混合检索并行执行 BM25（SQLite FTS5）与向量检索（Qdrant），结果经 Rerank 重排
  5. Top-K 证据交给 LLM 流式生成带引用的答案，逐字推送到前端
  6. 前端渲染答案、可点击引用与检索过程步骤

知识关联链（Wiki 概念层）

  1. 文档入库时，LLM 分批抽取概念、别名与概念间关系
  2. 概念锚点指向真实入库 chunks，形成"概念 ↔ 条文"的双向索引
  3. 查询时向 Agent 提供概念定位工具与别名查询扩展
  4. 跨文档概念（如"防火间距"同时锚定多本规范）构成知识网络，前端"知识网络"Tab 可浏览
