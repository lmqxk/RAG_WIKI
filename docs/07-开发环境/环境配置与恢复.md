# 环境配置与恢复

## 当前环境来源

本项目后端使用项目内虚拟环境：

```text
backend/.venv
```

该环境不是系统 Python，也不是全局 pip 环境，由 `uv` 创建/同步。

## 为什么终端识别不到 uv / pip / python

这些命令不在系统 `PATH` 中。另外当前虚拟环境里没有 pip 模块：

```powershell
.\backend\.venv\Scripts\python.exe -m pip --version
# No module named pip
```

这属于 `uv` 管理环境的常见形态：项目运行依赖已经装进 `.venv`，但不依赖虚拟环境里的 pip。

## 运行项目

优先使用项目固定入口：

```powershell
.\start.cmd
```

`start.cmd` 调用 `backend\.venv\Scripts\python.exe scripts\run.py`，启动：

| 服务 | 地址 |
| --- | --- |
| 后端 | http://127.0.0.1:8000 |
| 前端 | http://localhost:3000 |

Docker 部署模式见《Docker与vLLM技术细节》。两种模式共用 `storage/` 和 `.env`，可以随时切换，但**不要同时运行**（端口与 Qdrant 数据锁会冲突）。

## 后端常用命令

不依赖系统 `python`，直接用项目虚拟环境：

```powershell
# 跑测试
cd backend
.\.venv\Scripts\python.exe -m pytest --basetemp .pytest-tmp -o cache_dir=.pytest-cache-run

# 启动后端
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

使用 `uv` 时（需先安装 uv 或确保 `.tools/uv/bin/uv.exe` 在 PATH 中）：

```powershell
uv run --project backend pytest -q
```

## 依赖声明位置

后端依赖声明在 `backend/pyproject.toml` + `backend/uv.lock`。

核心依赖：

```text
fastapi  httpx  numpy  pydantic-settings  pymupdf  pypdf
python-multipart  qdrant-client  uvicorn
```

可选依赖组：`mineru`、`ocr`、`dev`。

## 恢复或重建后端环境

本机可用 `uv` 时：

```powershell
cd backend
uv sync --all-extras --group dev     # 完整开发环境
uv sync                              # 基础运行环境
uv sync --extra mineru --extra ocr --group dev   # MinerU + OCR
```

## 不建议的做法

不要直接用系统 pip 往项目里混装依赖：

- 当前 `.venv` 没有 pip。
- 系统 pip 可能写到别的 Python 环境。
- 项目已有 `uv.lock`，混装容易造成依赖版本和锁文件不一致。

## 环境排查命令

```powershell
Get-Content backend\.venv\pyvenv.cfg        # 虚拟环境来源
Get-ChildItem backend\.venv\Scripts          # 已安装入口
Invoke-WebRequest -Uri "http://127.0.0.1:8000/api/health" # 后端健康状态
```
